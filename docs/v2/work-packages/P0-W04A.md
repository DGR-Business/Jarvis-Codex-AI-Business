## Objective

Remove the two demonstrated P0 gate preconditions by correcting the exact
candidate-range documentation formatting defects and making Pantheon's exact
Python renderer reproducible through a durable, repository-supported,
Git-ignored local environment. Evaluate the current stable renderer releases
and adopt only the newest exact versions that Pantheon's existing behavior and
complete verification actually validate.

## Business reason

Pantheon should not fail because a managed Codex Python happens to carry a
different package set, nor should renderer pins remain stale merely because a
one-use environment once passed. The solution must remain a small development
and runtime prerequisite, not another assurance framework.

### Local renderer environment

- The canonical interpreter is
  `/.venv-renderer/Scripts/python.exe` on Windows and
  `/.venv-renderer/bin/python` elsewhere, resolved from the Git root rather than
  the current directory or a user profile.
- The generated environment is checkout-local by design and does not transfer
  through Git. W04A establishes and retains it in the implementation worktree;
  the deterministic bootstrap is how another checkout obtains the same exact
  environment. Do not copy or move a virtual environment between roots.
- Bootstrap accepts an explicit absolute base-Python path, verifies CPython
  3.13, creates a virtual environment without system-site packages, and
  installs only from the four exact direct pins plus resolver-required
  transitives. Every pip mutation must target the virtual-environment
  interpreter through `-m pip`.
- Package-index access is authorized only for this bootstrap and official
  release review. Use normal public release artifacts, no credentials/custom
  index, no provider/commercial action and no mutation of the base interpreter.
- The pip child uses the platform null file as `PIP_CONFIG_FILE`, an environment-
  local cache and no inherited user-site or custom-index setting. It must not
  read or print package-index credentials.
- Bootstrap and validation must be idempotent. Any recreate/delete operation
  must first prove the resolved target is the exact anchored
  `/.venv-renderer/` path inside the verified repository.
- Validation must fail closed unless the interpreter is a real file within the
  canonical local environment, `sys.prefix` proves virtual-environment
  isolation, user site packages are disabled, all renderer modules import,
  `pip check` passes and installed direct versions exactly equal the pins.
- Do not duplicate version literals in executable code. Read the exact contract
  from `requirements-runtime.txt`.
- Never print environment values, package-index credentials or owner data.

### Discovery and compatibility

- Preserve explicit `PANTHEON_PYTHON`/`JARVIS_PYTHON` compatibility. Where both
  aliases are required for provenance, accept them only when they are coherent
  absolute aliases of the same canonical exact-ready interpreter.
- Prefer the exact-ready repository-local environment over Codex-managed,
  user-cache or bare-command fallbacks for ordinary local development and test
  execution. A mismatched local environment must fail visibly; it must not
  silently fall through to a coincidentally compatible managed interpreter.
- Hosted CI may continue using its explicit setup-python interpreter and
  `requirements-runtime.txt`. Do not alter lifecycle semantics or run the
  quarantined lifecycle test locally.
- Use at most one small shared resolver/validator. Remove materially conflicting
  duplicate behavior rather than building a general environment framework.
- Existing strict fixture, artifact, workbook, PDF structure, deterministic-
  rendering and Doctor assertions must pass without being weakened. New
  focused evidence may be added; a blanket expected-output refresh is not
  compatibility proof.
- Try the complete newest-stable candidate set first. If a focused compatibility
  check fails, test each implicated new pin independently against the last known
  exact set, record the discriminating result, then make one final selection.
  Do not create an ongoing version-matrix harness.
